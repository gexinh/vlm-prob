# Tutorial revision: complete live workflows

## Goal

Make every public method learnable from its own guide, and make notebooks show
how results are produced from inputs rather than only how saved outputs are
displayed. This revision changes documentation and tutorial code; the package
runtime API and version remain unchanged.

## Difference from the previous tutorials

| Previous behavior | Current behavior |
| --- | --- |
| Short calls relied on `probe`, `inputs` and metrics defined elsewhere | Each method guide includes complete imports, model loading, input preparation, target/reference construction, execution and plotting |
| Parameter descriptions followed the example and omitted some training/run controls | API signatures and defaults/constraints come first, including calibration and integration settings |
| Notebook default paths loaded archived measurements and figures | All nine notebooks compute results before plotting; raw attributed inputs remain reusable |
| A model guide's few method calls could look like its full capability list | Guides explain the shared API, print the actual method inventory and document architecture-specific restrictions |
| Example figures came from separate report workflows | Nineteen preview figures are generated by runnable tutorial scripts, with source/model/input provenance |

The default text-lens notebook explicitly skips dense Attention Lens and exact
Jacobian calibration unless enabled. Their complete fitting code is visible,
and both standalone workflows were independently executed. Short calibration
splits are demonstrations rather than validated scientific decoders.

## Expected result

Readers can copy a complete method example, identify every required input and
parameter, produce a `ProbeResult`, save it and generate a corresponding figure.
Switching models changes loading, tokenization/image processing and supported
layers; the method API remains shared wherever the adapter provides its required
capabilities. Missing methods remain explicit, including hybrid Qwen3.5
propagation restrictions and the ViT vocabulary-readout boundary.

The expected improvement is reproducibility and usability of the examples.
This documentation revision does not establish an improvement in model accuracy
or the interpretability quality of a small calibration fit.

## Validation

- All 19 standalone method scripts ran on pretrained GPT-2, SmolVLM-500M or
  Google ViT-B/16, including actual dense Attention Lens fitting/restoration,
  exact Jacobian estimation and genuine DTD/LRP.
- All nine notebooks completed their default paths with inline figures and
  zero stored execution errors. Expensive skipped branches are labeled.
- Static checks compile example blocks, check local links and declared factory
  parameter coverage, and reject the old notebook replay-helper pattern.
- Preview manifests preserve model/data identities and figure checksums:
  [Lens](assets/tutorials/lens-provenance.json),
  [Attention](assets/tutorials/attention-execution.json),
  [Causal](assets/tutorials/causal-preview-provenance.json).

Run the static check with `python tools/validate_tutorials.py` from the
repository root. [demos/validation.json](../demos/validation.json) distinguishes
these checks from actual model execution. Original report measurement archives
remain reference data; no tutorial silently falls back to them.
